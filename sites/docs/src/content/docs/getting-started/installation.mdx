`cicord` is a single static binary: the command line tool **and** the runtime
(`cicord serve`), with the admin console, the default community portal and the plugin
toolkit embedded in it. Running it needs no Node.js: plugins are bundled by the runtime
itself (esbuild used as a Go library), git is handled in Go and SQLite is a pure Go driver.

:::caution[Pre-release]
Cicord is **v1alpha1**: `0.x` releases may still change formats and APIs. Read the
[changelog](https://github.com/cicord/cicord/blob/main/CHANGELOG.md) before upgrading.
:::

Every release (tag `v<version>`) publishes:

| What                       | Where                                                                                                          |
| -------------------------- | -------------------------------------------------------------------------------------------------------------- |
| Binaries                   | [GitHub Releases](https://github.com/cicord/cicord/releases): linux and darwin (amd64, arm64), windows (amd64) |
| Install script             | `https://cicord.dev/install.sh` (Linux, macOS): installs and verifies a release binary                         |
| Homebrew cask              | `cicord/tap/cicord` (macOS, Linux), from the release after 0.1.6                                               |
| npm package of the binary  | `@cicord/cli` (macOS, Linux, Windows), from a later release                                                    |
| Container image            | `ghcr.io/cicord/cicord:<version>` (linux/amd64, linux/arm64)                                                   |
| npm packages (portal, SDK) | `@cicord/sdk`, `@cicord/client`, `@cicord/react`, `@cicord/ui`                                                 |

## Install

Every method below installs the same binary, built by the release workflow. Pick one.

### Install script

Linux and macOS, amd64 and arm64:

```sh
curl -fsSL https://cicord.dev/install.sh | sh
```

The script downloads the archive of your platform and `checksums.txt` from the latest
GitHub Release, checks the SHA-256 of the archive, verifies its
[build provenance](#verify-a-download) with `gh attestation verify` when the
[GitHub CLI](https://cli.github.com/) is installed and logged in (otherwise it says so and
prints the command), then installs `cicord` and prints `cicord version`. It only reads the
terminal for `sudo`. Settings, as environment variables of `sh`:

| Variable             | Default                                                                          |
| -------------------- | -------------------------------------------------------------------------------- |
| `CICORD_VERSION`     | the latest release (pre-releases excluded); `0.1.6` or `v0.1.6`                  |
| `CICORD_INSTALL_DIR` | `/usr/local/bin` when it is writable or `sudo` is available, else `~/.local/bin` |

```sh
curl -fsSL https://cicord.dev/install.sh | CICORD_VERSION=0.1.6 CICORD_INSTALL_DIR="$HOME/bin" sh
```

To read the script before running it: `curl -fsSL https://cicord.dev/install.sh -o install.sh`,
then `sh install.sh`. Its source is
[`sites/landing/public/install.sh`](https://github.com/cicord/cicord/blob/main/sites/landing/public/install.sh).
Running it again upgrades `cicord`.

### Homebrew

:::note[From the release after 0.1.6]
The tap is published by the release workflow from the next release on. Until then, use the
install script.
:::

macOS and Linux:

```sh
brew install cicord/tap/cicord
brew upgrade cicord                # later releases
```

`cicord/tap/cicord` is a cask of the tap [`cicord/homebrew-tap`](https://github.com/cicord/homebrew-tap),
written by the release workflow for every release (never a pre-release). It installs the
release archive, checked against the SHA-256 of `checksums.txt`. The binaries are not
notarized by Apple, so on macOS the cask removes the quarantine attribute after installing.

### npm

:::note[From a later release]
`@cicord/cli` is not published yet: it will be from a later release on. Until then, use the
install script.
:::

macOS (arm64, x64), Linux (x64, arm64) and Windows (x64), with Node.js 18 or later:

```sh
npm i -g @cicord/cli
npx @cicord/cli version            # without installing it
```

`@cicord/cli` has one optional dependency per platform, `@cicord/cli-<os>-<arch>` at the
same version, which holds the release binary; npm only installs the one of your machine, and
the `cicord` command runs it (same arguments, output and exit code). Do not install with
`--omit=optional` (or `--no-optional`): the binary would be missing. The packages are
published with [npm provenance](#verify-a-download), and the binaries in them are the release
archives' after the workflow checked their checksums and attestations.

### Container image

The image `ghcr.io/cicord/cicord` is built from the repository's `Dockerfile` for
linux/amd64 and linux/arm64: `cicord` on `gcr.io/distroless/static-debian13:nonroot` (user
65532, no shell), with a `HEALTHCHECK` (`cicord healthcheck`). Tags: `<version>` (`0.1.6`),
`<major>.<minor>` (`0.1`) and `latest` for releases without a pre-release suffix, and
`sha-<commit>`.

```sh
docker pull ghcr.io/cicord/cicord:0.1.6                                      # pin the version in production
gh attestation verify oci://ghcr.io/cicord/cicord:0.1.6 --repo cicord/cicord    # see Verify a download
docker run --rm ghcr.io/cicord/cicord:0.1.6 version                          # the entrypoint is cicord
```

The default command is `cicord serve /repo --data-dir /data --listen :7420`, with a volume on
`/data` and port `7420`. Running it in production is covered in
[Deploy](../../self-hosting/deploy/#docker).

### Manual download

<Steps>

1. Pick the version and your platform, then download the archive and `checksums.txt` from
   the release (with the [GitHub CLI](https://cli.github.com/), or from the
   [Releases](https://github.com/cicord/cicord/releases) page):

   ```sh
   VERSION=0.1.6 OS=linux ARCH=amd64     # OS: linux | darwin, ARCH: amd64 | arm64
   gh release download "v$VERSION" --repo cicord/cicord \
     --pattern "cicord_${VERSION}_${OS}_${ARCH}.tar.gz" --pattern checksums.txt
   ```

   On Windows, the archive is `cicord_<version>_windows_amd64.zip` and holds `cicord.exe`.

2. Verify it (see [Verify a download](#verify-a-download)):

   ```sh
   sha256sum --ignore-missing -c checksums.txt     # macOS: shasum -a 256 --ignore-missing -c checksums.txt
   gh attestation verify "cicord_${VERSION}_${OS}_${ARCH}.tar.gz" --repo cicord/cicord
   ```

3. Extract `cicord` and put it on your `PATH`:

   ```sh
   tar -xzf "cicord_${VERSION}_${OS}_${ARCH}.tar.gz" cicord
   sudo install cicord /usr/local/bin/
   ```

   The archive also holds `LICENSE`, `NOTICE` and `README.md`. The binaries are not signed
   for macOS Gatekeeper: if you downloaded the archive with a browser, remove the quarantine
   flag with `xattr -d com.apple.quarantine cicord`.

</Steps>

### go install

```sh
go install github.com/cicord/cicord/cmd/cicord@latest
```

This builds the command line tool **without** the embedded web UIs: the admin console and
the default portal are placeholders, `cicord portal init` has no kit, and `cicord version`
shows the commit `dev`. It is enough for CI (`cicord validate`, `cicord plan --remote`,
`cicord status --wait`), which is how the workflow written by `cicord init` installs it, not
for running the runtime.

### Build from source

| Tool               | Needed for                                                                                                                                                   |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Go 1.27**        | Building the `cicord` binary (`CGO_ENABLED=0`, a static binary).                                                                                             |
| **Node 26 + pnpm** | Building the embedded web UIs (admin console, default portal) and the portal kit. The pnpm version is pinned by `packageManager` in the root `package.json`. |
| **git**            | Cloning the repository.                                                                                                                                      |

<Steps>

1. Clone the repository (or a release tag: `--branch v0.1.6`) and enter it:

   ```sh
   git clone https://github.com/cicord/cicord.git
   cd cicord
   ```

2. Build everything:

   ```sh
   make all VERSION=0.1.6
   ```

   `make all` runs `make ui` (installs the JS workspace with `pnpm install --frozen-lockfile`,
   builds the packages and copies the admin console, the portal and the portal kit into
   `internal/webui`), then `make build`, which writes `bin/cicord`. `VERSION` is what
   `cicord version` prints; the commit comes from git.

3. Put `bin/cicord` on your `PATH`, or call it by its path:

   ```sh
   export PATH="$PWD/bin:$PATH"
   ```

</Steps>

:::note
`make build` alone builds only the Go binary. It embeds whatever UI build is already in
`internal/webui`, which is a placeholder on a fresh clone. Without the portal kit,
`cicord portal init` explains how to build it, and `cicord plugin new` scaffolds plugins
without their unit-test setup. Use `make all` unless you only work on Go code.
:::

The same image as the release builds locally with
`docker build -t cicord --build-arg VERSION=0.1.6 --build-arg COMMIT=$(git rev-parse --short HEAD) .`

## Verify a download

Each release is built by the repository's release workflow on GitHub Actions, which signs
**build provenance attestations** (Sigstore) for every archive and for the image: proof that
the file was built by `cicord/cicord`'s `.github/workflows/release.yml` from the tagged
commit.

- **Checksums**: `checksums.txt` lists the SHA-256 of every archive and SBOM:
  `sha256sum --ignore-missing -c checksums.txt`.
- **Archive provenance**: `gh attestation verify <archive> --repo cicord/cicord` (add
  `--signer-workflow cicord/cicord/.github/workflows/release.yml` to also pin the workflow).
- **SBOM**: every archive has an SPDX SBOM next to it on the release,
  `<archive>.sbom.json`.
- **Image provenance**:
  `gh attestation verify oci://ghcr.io/cicord/cicord:<version> --repo cicord/cicord`. The
  image also carries BuildKit's SBOM and SLSA provenance:
  `docker buildx imagetools inspect ghcr.io/cicord/cicord:<version> --format '{{ json .SBOM }}'`
  (or `.Provenance`). The attestation is stored in the registry too, so
  `cosign verify-attestation` works without the GitHub API (see
  [Releasing](../../project/releasing/#verifying-a-release)).
- **npm packages**: published by the repository's `release-npm.yml` workflow with
  [provenance](https://docs.npmjs.com/generating-provenance-statements): the npm page of each
  package shows the provenance badge, and `npm audit signatures` checks them in your project.

Then check the installation:

```sh
cicord version
```

```text
cicord 0.1.6 (ebc3e05)
```

The version, then the git commit the binary was built from. `cicord --help` lists the
commands.

## Editor support

Every file has a JSON Schema, published at `https://cicord.dev/schemas/v1alpha1/`
(`project`, `server`, `bot` and `plugin`; the sources are in `spec/schemas/`). With the YAML
language server (VS Code YAML extension and others), a schema comment at the top of a file
gives completion and validation:

```yaml title="servers/cicord.yaml"
# yaml-language-server: $schema=https://cicord.dev/schemas/v1alpha1/server.schema.json
apiVersion: cicord.dev/v1alpha1
kind: Server
```
